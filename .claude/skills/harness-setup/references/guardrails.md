# Фаза 5. Ограждения

Хуки запрещают агенту менять файлы обвязки, поэтому порядок шагов важен. `settings.json` записывается последним.

## Первая установка и повторный запуск

- **Проект из шаблона-основы.** Хуки, настройки и `harness.env` уже лежат в проекте. Агент заполняет команды проекта и прогоняет автотест.
- **Проект без шаблона.** Агент выполняет шаги 1–6 сам. `settings.json` записывается последним, потому что включает защиту.
- **Повторный запуск и обновление.** Файлы обвязки проекта меняются только правкой файла, через терминал это запрещено: в запросе должно быть видно, что меняется. Claude Code показывает пользователю изменения, пользователь одобряет их в приложении.
- **Правки, выключающие защиту,** агенту запрещены совсем: `disableAllHooks: true`, режим bypass, удаление хуков обвязки, выключение гейтов, запись в `settings.local.json`. Если такая правка действительно нужна, человек делает её в веб-редакторе GitHub.

## 1. harness.env

```bash
mkdir -p .claude
cp "<папка скилла>/hooks/harness.env.template" .claude/harness.env
```

| Переменная | Что вписать |
|---|---|
| `HARNESS_GATES_ACTIVE` | `1`, если настоящие тесты уже есть. Для нового проекта `0` до первого теста |
| `HARNESS_FAST_CHECK_CMD` | Быстрая проверка после правки: линтер, типы, быстрые тесты. Цель до 30 секунд |
| `HARNESS_TEST_CMD` | Полный набор тестов для гейтов коммита и завершения хода |
| `HARNESS_CHECK_SKIP_REGEX` | Файлы, после правки которых быстрая проверка не нужна |
| `HARNESS_MAX_EDITS_PER_FILE` | Порог предупреждения о зацикливании |
| `HARNESS_REQUIRE_STATE_UPDATE` | `1` напоминает обновить docs/STATE.md перед завершением хода с изменённым кодом |
| `HARNESS_STOP_MAX_BLOCKS` | Сколько раз подряд гейт завершения хода блокирует при красных тестах, прежде чем отпустить и позвать человека |
| `HARNESS_ENV_FIXTURE_REGEX` | Файлы окружения без секретов, которые агенту можно писать, например `.env.test` |

Покажи пользователю итоговый файл.

## 2. Хуки

```bash
mkdir -p .claude/hooks
cp "<папка скилла>"/hooks/*.sh .claude/hooks/
```

| Хук | Событие | Что делает |
|---|---|---|
| `block-dangerous.sh` | PreToolUse, Bash | Запрещает удаление корня, дома и `.git`, force push, `curl \| sh`, правку файлов обвязки проекта через терминал и любую запись в глобальные настройки `~/.claude`. Спрашивает подтверждение на `git reset --hard`, `git checkout .`, удаление удалённых веток, `sudo`, `DROP TABLE`, публикацию пакетов |
| `secret-guard.sh` | PreToolUse, Write и Edit | Не даёт писать в `.env`, `.envrc`, `settings.local.json`, глобальные настройки и код со строками, похожими на ключи. Запрещает правки, выключающие защиту: `disableAllHooks`, режим bypass, удаление хуков обвязки, выключение гейтов. Остальные правки файлов обвязки проекта отправляет на подтверждение |
| `after-edit-check.sh` | PostToolUse, Write и Edit | Запускает быструю проверку, возвращает ошибку агенту, предупреждает о зацикливании |
| `commit-gate.sh` | PreToolUse, команды git | Запрещает коммит при красных тестах |
| `stop-gate.sh` | Stop | Не даёт закончить ход с красными тестами, но не больше `HARNESS_STOP_MAX_BLOCKS` раз за ход. Сдавшееся состояние не блокирует следующие ходы, пока код не изменится. Напоминает обновить STATE.md |
| `harness-status.sh` | SessionStart | Передаёт Claude статус проекта, чтобы навигатор предложил следующий шаг |
| `_harness_lib.sh` | нет | Общий разбор команд для хуков. Сам не запускается, но без него хуки Bash не работают |

Гейты `after-edit-check`, `commit-gate` и `stop-gate` молчат, пока `HARNESS_GATES_ACTIVE=0`. Так тесты не воюют с фазой планирования, когда проверять ещё нечего.

Хуки на регулярных выражениях это страховочная сетка. Глобы, переменные и скрипты на других языках их обходят. Основная защита: правила прав, песочница Claude Code и ревью.

## 4. Автотест хуков

```bash
bash "<папка скилла>/hooks/smoke-test.sh" .claude/hooks
```
Тест работает во временной папке и проект не трогает. Он проверяет копии хуков в проекте, скрипт слияния и шаблон прав. Любой FAIL останавливает фазу.

## 5. settings.json

1. Скопируй шаблон в рабочую папку и впиши в `permissions.allow` реальные команды проекта, например `Bash(npm test *)` или `Bash(pytest *)`:
   ```bash
   mkdir -p .harness/runtime
   cp "<папка скилла>/hooks/settings.template.json" .harness/runtime/settings.template.json
   ```
2. Слей шаблон с текущими настройками. Скрипт идемпотентный: повторный запуск ничего не дублирует, пользовательские правила сохраняют порядок. Правила и хуки обвязки из прошлых версий шаблона он заменяет текущими. Если `settings.json` не валидный JSON, скрипт останавливается с ошибкой.
   ```bash
   if bash "<папка скилла>/scripts/merge-settings.sh" .claude/settings.json .harness/runtime/settings.template.json > .harness/runtime/settings.merged.json; then
     diff -u .claude/settings.json .harness/runtime/settings.merged.json
   else
     rm -f .harness/runtime/settings.merged.json
   fi
   ```
3. После согласия пользователя при первой установке перенеси файл на место:
   ```bash
   mv .harness/runtime/settings.merged.json .claude/settings.json
   ```
   При повторном запуске этот шаг выполняет человек.

Что важно про правила прав:
- порядок проверки: deny, потом ask, потом allow, и исключение в allow не ослабит deny;
- путь со слешем в начале, например `/.claude/hooks/**`, привязан к корню проекта для проектных настроек;
- правила `Write(...)` Claude Code не проверяет, для файлов работают только `Edit(...)` и `Read(...)`;
- deny на `Read` для пути заодно запрещает запись в этот путь;
- шаблон ставит `disableAllHooks: false` на уровне проекта, это перекрывает попытку выключить хуки в глобальных настройках.

## 6. Обновление файлов обвязки

Агент готовит новые версии в `.harness/runtime/`, показывает diff и переносит их по одному файлу правкой. Копирование папкой через терминал хуки запрещают: в команде не видно содержимого. Каждую правку `.claude/hooks`, `.claude/skills`, `.claude/settings.json` и `.claude/harness.env` пользователь подтверждает в приложении. Скиллы защищены наравне с хуками: в исследовательском проекте там лежит и проверка вики, то есть сами ворота. После обновления агент прогоняет автотест хуков и аудит.

## 7. Перезапуск

Скажи пользователю: закрыть сессию, открыть Claude Code в папке проекта и вызвать `/harness-setup --resume`. Проверить загруженные хуки можно в меню `/hooks`.
