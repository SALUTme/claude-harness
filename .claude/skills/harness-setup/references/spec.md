# Фаза 6. Спецификация

## Выбор системы

| Ситуация | Совет | Почему |
|---|---|---|
| Новый проект | Spec Kit | Конституция проекта, затем спецификация, план и задачи |
| Существующий код | OpenSpec | Дельта-спецификации описывают только изменения |

Выбор за пользователем. Ставь одну систему. Две системы спорят о формате документов.

## Spec Kit

Установка, только с согласия. Версию фиксируем, чтобы проекты не расходились:
```bash
TAG=$(git ls-remote --tags --refs --sort=-v:refname https://github.com/github/spec-kit.git 'v*' | head -n 1 | sed 's#.*refs/tags/##')
[ -n "$TAG" ] && echo "Spec Kit $TAG" && if command -v uv >/dev/null 2>&1; then uv tool install specify-cli --from "git+https://github.com/github/spec-kit.git@${TAG}"; else pipx install "git+https://github.com/github/spec-kit.git@${TAG}"; fi
```
В облачной сессии `uv` уже есть, но установка пропадает вместе с виртуальной машиной. Чтобы не ставить Spec Kit каждый раз, предложи пользователю добавить эту команду в скрипт подготовки облачного окружения. Запиши версию в `docs/HARNESS.md`. Если тег оказался пре-релизом, например с суффиксом `rc`, спроси пользователя, ставить ли его.

Инициализация в текущей папке:
```bash
specify init --here --integration claude --non-interactive
```
Если команда отказывается работать в непустой папке, сначала закоммить текущее состояние. Флаг `--force` добавляй только после согласия пользователя.

После инициализации проверь, какие команды появились в `.claude/commands` или `.claude/skills`. Обычно это `/speckit.constitution`, `/speckit.specify`, `/speckit.plan`, `/speckit.tasks`, `/speckit.implement`. Если модель не может вызвать команду сама, попроси пользователя ввести её.

Порядок:
1. Конституция: инварианты из NORTH_STAR.md и правила из CLAUDE.md.
2. Спецификация: что и зачем из PRD, без стека.
3. Уточнения, если в версии есть команда уточнения.
4. План: стек и архитектура.
5. Задачи.

## OpenSpec

Установка, только с согласия, с фиксированной версией:
```bash
VER=$(npm view @fission-ai/openspec version)
npm install -g "@fission-ai/openspec@${VER}"
```
Запиши версию в `docs/HARNESS.md`.

Инициализация:
```bash
openspec init --tools claude
```

Порядок:
1. `/opsx:explore`, чтобы агент изучил код и варианты.
2. `/opsx:propose <изменение>` из PRD. Получатся proposal, specs, design и tasks.
3. Реализация через `/opsx:apply`, после приёмки `/opsx:archive`.

## Приёмка

`docs/ACCEPTANCE.md` по шаблону. Правила:
- у каждого критерия ID, ссылка на требование PRD и команда проверки;
- ручная проверка допустима только с причиной и именем того, кто проверяет;
- команда проверяет поведение, а не наличие кода;
- тест, который сам чинит то, что проверяет, считается проваленным.

Не копируй PRD в спецификацию. Ссылайся на него.
