# Фаза 1. Интервью

## Измерения обвязки

Интервью закрыто, когда у каждого измерения есть ответ. Допустим ответ «пока неизвестно, решим в фазе N».

| # | Измерение | Что выяснить |
|---|---|---|
| 1 | Цель | Одно предложение о ценности продукта и для кого он |
| 2 | Готовность MVP | Наблюдаемые признаки, по которым понятно, что первая версия готова |
| 3 | Стек | Язык, фреймворки, платформа, ограничения на выбор |
| 4 | Режим | Новый проект или существующий. Для существующего: что трогать нельзя |
| 5 | Команды | Установка, сборка, тесты, линтер, проверка типов, запуск. Если их нет, какие хотим |
| 6 | Данные и секреты | Есть ли прод-данные и персональные данные, где живут ключи, есть ли тестовые ключи |
| 7 | Внешние системы | API, базы, очереди, платёжки. Есть ли песочницы |
| 8 | Автономия | Интерактивно, одобрение плана и дальше сам, или полностью автономно. Сколько итераций максимум |
| 9 | Эскалация | Какие решения принимает только человек и как до него достучаться |
| 10 | Проверка | Кто ревьюер, нужен ли ревью-гейт на каждый ход или на этап |
| 11 | Окружения | Где запускается, какие службы нужны для тестов (база, очередь, кэш), есть ли CI, нужен ли тестовый стенд с превью, как устроен деплой |
| 12 | Бюджет | Ограничения по деньгам и токенам |
| 13 | Люди | Кто ещё работает в репозитории |
| 14 | Знания | Какие документы, базы и заметки уже есть и куда складывать новые |
| 15 | Риски | Чего пользователь больше всего опасается |

## Работа с deep-interview

1. Перед запуском скажи пользователю: «В конце интервью спросит, как исполнять спецификацию. Там только варианты запуска: Ralplan с Autopilot, Autopilot, Ralph, Team, и ещё продолжить уточнение. Остановиться в списке нет, поэтому выбери свой ответ и напиши: стоп, вернуться в harness-setup».
2. Запусти `oh-my-claudecode:deep-interview` с идеей пользователя. Для небольших проектов подойдёт `--quick`, для крупных `--standard`.
3. Если пользователь всё же выбрал вариант исполнения, не запускай его. Спроси, точно ли он хочет уйти из harness-setup.
4. После интервью возьми самый свежий `.omc/specs/deep-interview-*.md`.
5. Сбрось состояние интервью: инструмент `state_clear` из oh-my-claudecode с параметром `mode: deep-interview`.
6. Сопоставь спецификацию с таблицей измерений. Отметь, какие закрыты.
7. Недостающие измерения спрашивай сам.

## Своё интервью, если deep-interview недоступен

1. Один вопрос за раз.
2. Каждый вопрос бьёт в самое слабое измерение. Скажи, какое измерение закрываешь и почему сейчас.
3. Для существующего кода сначала найди факты в репозитории, потом спрашивай. В вопросе ссылайся на найденный файл.
4. После каждого ответа покажи короткий прогресс: закрыто N из 15, дальше такое-то измерение.
5. Если пользователь хочет закончить раньше, покажи незакрытые измерения и риск.

## Результат

`docs/BRIEF.md` по шаблону. Ответы пользователя передавай его формулировками, не приукрашивай.
