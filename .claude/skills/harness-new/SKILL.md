# harness-new: новый проект из основы

Пользователь не запоминает команды. Ты создаёшь репозиторий сам и говоришь, что делать дальше. Общайся на языке пользователя. Аргументы: `$ARGUMENTS`.

## 1. Где идёт сессия

Если `CLAUDE_CODE_REMOTE` равно `true`, это облачная сессия. Облако не создаёт репозитории: доступ к GitHub там ограничен репозиториями этой сессии. Скажи пользователю два способа и остановись:
1. Открыть `https://github.com/<основа>/generate`, выбрать **Private**, ввести название и нажать **Create repository**.
2. Написать «создай новый проект» в сессии на Mac, в том числе через Remote Control.

## 2. Доступ к GitHub

Вход в GitHub может быть сохранён в `gh`, а переменная `GITHUB_TOKEN` в профиле оболочки может его перекрывать. Проверь оба варианта одной командой:
```bash
if env -u GH_TOKEN -u GITHUB_TOKEN gh auth status >/dev/null 2>&1; then echo GH="env -u GH_TOKEN -u GITHUB_TOKEN gh"; elif gh auth status >/dev/null 2>&1; then echo GH=gh; else echo GH=none; fi
```
Дальше во всех командах вместо `gh` пиши то, что вывела проверка. Если `GH=none`, объясни, что нужен вход в GitHub, и предложи пользователю ввести в Claude Code строку `! gh auth login --web`. Вход выполняет только сам пользователь.

## 3. Параметры

1. Основа: поле `repo` в `.harness/source.json` текущей папки, если файл есть и поле заполнено. Иначе `SALUTme/claude-harness`.
2. Владелец: `gh api user --jq .login`.
3. Название: из аргументов, иначе спроси. Допустимы латинские буквы, цифры, `-`, `_` и `.`. Если пользователь назвал проект по-русски, предложи латинское название через дефис.
4. Проверь, что имя свободно: `gh repo view ВЛАДЕЛЕЦ/НАЗВАНИЕ`. Если репозиторий уже есть, попроси другое название.
5. Попроси одну фразу о проекте для описания репозитория. Можно пропустить.

## 4. Создание

Создание репозитория это действие на GitHub. Перед ним покажи владельца, название, приватность и основу и получи явное согласие через `AskUserQuestion`.

```bash
gh repo create ВЛАДЕЛЕЦ/НАЗВАНИЕ --private --template ОСНОВА --description "ОПИСАНИЕ"
```

Проверь, что файлы основы скопировались:
```bash
gh api repos/ВЛАДЕЛЕЦ/НАЗВАНИЕ/contents/.harness/source.json --jq .name
```
GitHub копирует шаблон несколько секунд. Если файла ещё нет, скажи об этом и проверь снова следующим сообщением. Не пиши циклы ожидания.

Workflow `harness-update.yml` в новом проекте открывает PR с обновлениями обвязки. Для этого репозиторию нужно разрешение «Allow GitHub Actions to create and approve pull requests». Спроси через `AskUserQuestion`, включить ли его. Если да, сохрани текущие права по умолчанию и включи только эту галочку:
```bash
p=$(gh api repos/ВЛАДЕЛЕЦ/НАЗВАНИЕ/actions/permissions/workflow --jq .default_workflow_permissions) && gh api -X PUT repos/ВЛАДЕЛЕЦ/НАЗВАНИЕ/actions/permissions/workflow -f default_workflow_permissions="$p" -F can_approve_pull_request_reviews=true
```
Если нет, скажи, что обновления обвязки тогда придётся запускать вручную, и где включить галочку потом: Settings → Actions → General.

## 5. Что дальше

Дай ссылку `https://github.com/ВЛАДЕЛЕЦ/НАЗВАНИЕ` и спроси через `AskUserQuestion`, где работать:

1. **В облаке, рекомендуется.** Скажи:
   - открыть в приложении Claude вкладку Code и выбрать репозиторий;
   - если его нет в списке, открыть `https://github.com/settings/installations`, в приложении Claude добавить репозиторий в доступ;
   - написать «привет», дальше поведёт навигатор.
2. **На этом Mac.** Спроси папку, по умолчанию `~/Projects`. Склонируй: `gh repo clone ВЛАДЕЛЕЦ/НАЗВАНИЕ ПАПКА/НАЗВАНИЕ`. Скажи открыть новую сессию в этой папке и написать «привет».

Подготовку проекта в этой сессии не начинай: она идёт в сессии нового репозитория.
