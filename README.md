# claude-harness

Основа для проектов с Claude Code. Внутри скиллы, хуки и навигатор, которые ведут проект от идеи до результата по одному порядку.

Есть два режима, выбор делается один раз при подготовке:

- **Код.** Ворота это тесты проекта, спецификации через Spec Kit или OpenSpec, CI и тестовый стенд.
- **Исследование.** Проект без кода: собираем данные, ведём вики, делаем таблицы, схемы и отчёты. Ворота это проверка вики: источники, живые ссылки, журнал, связность.

Репозиторий помечен как шаблон. Каждый новый проект создаётся его копией, поэтому всё нужное лежит прямо в репозитории проекта и работает везде: в приложении на Mac, через Remote Control и в облачных сессиях с телефона.

## Как начать новый проект

**Проще всего:** в любой сессии Claude Code на Mac, в том числе через Remote Control с телефона, напиши «создай новый проект». Скилл `harness-new` спросит название, создаст приватный репозиторий из этой основы и скажет, что делать дальше.

**Вручную, с любого устройства:**

1. Открой этот репозиторий на GitHub, нажми **Use this template**, затем **Create a new repository**. Выбери **Private** и название проекта. С телефона это работает в браузере.
2. Проверь, что приложение Claude на GitHub видит новый репозиторий. Если в его настройках на GitHub выбран доступ только к отдельным репозиториям, добавь туда новый. Иначе репозиторий не появится во вкладке Code.
3. В приложении Claude открой вкладку **Code** и выбери новый репозиторий.
4. Напиши что угодно, например «привет» или «что дальше».

Claude сам скажет, на каком этапе проект, и предложит следующий шаг вариантами ответа. Команды запоминать не нужно.

## Что внутри

| Путь | Что это |
|---|---|
| `.claude/skills/harness` | Навигатор. Определяет этап и предлагает следующий шаг |
| `.claude/skills/harness-setup` | Подготовка проекта по фазам: интервью, PRD или план исследования, скиллы, вики, хуки, спецификация, проверка, окружение и CI |
| `.claude/skills/harness-new` | Создание нового проекта из этой основы |
| `.claude/hooks/` | Хуки: защита от опасных команд, утечки секретов и отключения защиты, проверки тестов, статус проекта и подготовка окружения при старте сессии |
| `.claude/settings.json` | Подключение хуков, правила прав, плагины oh-my-claudecode и Codex |
| `.claude/harness.env` | Команды проверок проекта, заполняются при подготовке |
| `.harness/` | Состояние подготовки и адрес этой основы |
| `.github/workflows/harness-update.yml` | PR с обновлением обвязки, когда основа новее проекта |
| `.github/workflows/harness-selftest.yml` | Самопроверка основы. В проектах не запускается |
| `CLAUDE.md` | Стартовый файл, заменяется при подготовке проекта |

## Облачные сессии

- Плагины oh-my-claudecode и Codex объявлены в `.claude/settings.json`, облачная сессия ставит их сама при старте.
- Codex в облаке не работает: он входит по подписке через браузер. В облаке ревью делает агент oh-my-claudecode, а изменение попадает в список «Ревью Codex на Mac» в `docs/STATE.md`. В следующей сессии на Mac навигатор предложит прогнать эти ревью через Codex.
- Зависимости и службы проекта ставит хук подготовки окружения в начале каждой облачной сессии. На Mac он запускается автоматически, только если это включено в `.claude/harness.env`. Если облаку не хватает системных пакетов или доступа к сайту, этап «Окружение» пошагово объяснит, что добавить в настройки облака на claude.ai/code.
- Создавать новые репозитории облако не может. Для этого есть сессия на Mac или кнопка **Use this template**.

## Скилл «новый проект» на Mac

Чтобы фраза «создай новый проект» работала в любой папке на Mac, скилл `harness-new` лежит ещё и в `~/.claude/skills/harness-new`. После изменения скилла в основе обнови эту копию: скажи в сессии основы «обнови личную копию harness-new».

## Как обновить существующий проект

Обновление приходит само, в виде PR. Workflow `.github/workflows/harness-update.yml` в проекте раз в день сверяет версию проекта с основой. Если основа новее, он переносит её скриптом `harness-sync.sh`, прогоняет автотест хуков и открывает PR «Обвязка harness X → Y» с описанием изменений. Ты смотришь diff и сливаешь PR, в том числе с телефона. Чтобы не ждать до завтра, во вкладке **Actions** проекта выбери **Harness update** и нажми **Run workflow**.

Что переносится. Хуки и скиллы обвязки заменяются версией основы. Настройки сливаются: права и хуки проекта остаются. В `harness.env` добавляются только новые ключи. В состояние подготовки и `docs/STATE.md` добавляются новые фазы и разделы. Файлы проекта, `project-setup.sh` и свои скиллы не меняются.

Чтобы workflow мог открывать PR, в настройках проекта нужна галочка Settings → Actions → General → «Allow GitHub Actions to create and approve pull requests». Скилл `harness-new` предлагает включить её при создании проекта.

**Первое подключение.** В проектах, созданных до версии 0.4.0, workflow ещё нет. Встроенный токен GitHub не может менять файлы workflow, поэтому их переносят вручную, один раз. Это же нужно, если в PR есть пункт про `.github/workflows/harness-*.yml`. В терминале в папке проекта выполни:
```bash
T=$(mktemp -d) && git clone -q --depth 1 https://github.com/SALUTme/claude-harness.git "$T" && bash "$T/.claude/skills/harness-setup/scripts/harness-sync.sh" "$T" .
```
Скрипт напечатает, что изменил. Проверь `git diff` и закоммить. Можно попросить Claude в сессии проекта «обнови обвязку из основы»: он подскажет ту же команду и потом прогонит проверки.

## Изменения основы

- **0.4.1.** В предполётной проверке появился шаг «Git и GitHub», справочник `references/github.md`. Шаг задаёт имя и почту для коммитов, по умолчанию анонимный адрес GitHub. Перед первым коммитом и push проверяет, что секреты не попадут в репозиторий. Делает первый коммит, если коммитов нет. Для проекта без GitHub предлагает создать приватный репозиторий и включить разрешение для PR с обновлениями обвязки. Аудит предупреждает о проекте без коммитов и без `origin`.
- **0.4.0.** Обновления обвязки приходят в проекты сами, в виде PR. Новый скрипт `scripts/harness-sync.sh` переносит обвязку из основы и сохраняет настройки и файлы проекта. Новый workflow `harness-update.yml` раз в день открывает PR, когда основа новее. Основа стала публичной, поэтому токены не нужны. Аудит проверяет, что в проекте есть `harness-update.yml`. `harness-new` предлагает включить разрешение для PR от GitHub Actions. Навигатор обновляет проект через этот PR. При переходе на 0.4.0 один раз выполни команду из раздела «Первое подключение»: workflow не переносятся встроенным токеном.
- **0.3.1.** Аудит сверяет версию проекта с основой через `gh` и подсказывает обновиться, после обновления навигатор записывает новую версию в `.harness/source.json`. Защита от секретов ловит боевые ключи Stripe и секреты вебхуков, спрашивает про JWT и теперь видит секреты в командах терминала: запись в файл запрещена, остальное только с подтверждения. Гейт коммита не перезапускает тесты, если те же изменения, включая документы и эталоны, уже были зелёными в нём или в гейте конца хода. Гейты правильно работают, когда проект лежит в подпапке репозитория. У основы появился CI `harness-selftest.yml`: автотест на Linux и macOS, синтаксис скриптов, совпадение копий хуков и шаблонов. В проектах эта задача пропускается. Автотест из `.claude/hooks` теперь полный. При обновлении проекта переносятся хуки, скилл `harness` и `audit.sh`. Настройки и `harness.env` по смыслу не меняются.
- **0.3.0.** Режим «исследование»: тип проекта в `.harness/bootstrap-state.json`, проверка вики `scripts/wiki-lint.sh` вместо тестов, свои шаблоны плана, задач и правил качества, настраиваемые границы ворот в `harness.env`. Скиллы в `.claude/skills/` теперь защищены наравне с хуками. При обновлении проекта навигатор добавляет поле `kind` в состояние подготовки, ключ `HARNESS_GATE_EXCLUDE_REGEX` в `.claude/harness.env` и правило `Edit(/.claude/skills/**)` в настройки. Проекты с кодом без этих правок работают по-прежнему.
- **0.2.0.** Плагины в настройках, этап «Окружение» с подготовкой окружения и CI, отложенные ревью Codex, скилл `harness-new`. При обновлении проекта навигатор добавляет новую фазу в `.harness/bootstrap-state.json`, раздел «Ревью Codex на Mac» в `docs/STATE.md` и новые ключи в `.claude/harness.env`.

## Как менять саму основу

Изменения вносятся в этот репозиторий. Проекты внутри него не готовят: навигатор это распознаёт и предлагает только работу над основой. Перед коммитом Claude прогоняет автотест хуков, а после push то же самое на Linux и macOS делает CI `harness-selftest.yml`. Он же проверяет, что копии хуков в `.claude/hooks` и в скилле `harness-setup` совпадают и что версия из `.harness/source.json` описана в разделе «Изменения основы». Новые проекты получают новую версию сразу, старые получат PR с обновлением в течение суток. Не забудь поднять `version` в `.harness/source.json` и описать изменения выше: без новой версии PR в проектах не появится.

## Ограничения

- Плагины закреплены на проверенных версиях: oh-my-claudecode v4.13.0 и Codex v1.0.4. Это чужой код, он работает в каждой сессии без проверок хуков. Новую версию закрепляй в основе только после проверки.
- Хук подготовки окружения запускает менеджеры пакетов, а они читают файлы проекта, которые агент меняет без подтверждения. Поэтому на Mac автозапуск выключен по умолчанию.
- Remote Control работает, пока Mac включён и приложение открыто.
- Правки, которые выключают защиту, агенту запрещены. Если такая правка действительно нужна, её делает человек в веб-редакторе GitHub.
- Хуки это страховочная сетка, а не песочница. Основная защита: права Claude Code, подтверждения и ревью.
