# Фаза 7. Роли проверки

## Принципы

1. Автор и проверяющий разные: другая модель и чистый контекст.
2. Сначала детерминированные проверки хуками, потом ревью моделью.
3. Проверка идёт против задачи и `docs/ACCEPTANCE.md`, а не против собственного кода.
4. Итоговый вердикт выносит один проверяющий. Параллельные проверяющие без главного дают противоречивые сигналы.

## Codex как ревьюер

Codex работает только там, где установлен его CLI и выполнен вход по подписке. Это Mac, в том числе сессия через Remote Control с телефона.

В облачной сессии, где `CLAUDE_CODE_REMOTE=true`, Codex не используется:
1. Ревью делает запасной вариант ниже.
2. Добавь в `docs/STATE.md` в раздел «Ревью Codex на Mac» строку `- [ ] ветка, коммит, что проверить`.
3. В сессии на Mac навигатор предложит прогнать отложенные ревью. После ревью отметь строку `- [x]` и закрой замечания.

1. Проверь CLI: `command -v codex`.
2. Если его нет, с согласия пользователя:
   ```bash
   npm install -g @openai/codex
   ```
   Вход в аккаунт выполняет сам пользователь. Предложи ему ввести в Claude Code строку `! codex login`.
3. Проверка готовности плагина: команда `/codex:setup`.
4. Каждый вызов Bash идёт в отдельной оболочке, и переменные между вызовами не сохраняются. Поэтому поиск скрипта плагина и сам вызов пишутся одной командой.
5. Обычное ревью рабочей копии:
   ```bash
   CODEX_COMPANION=$(ls ~/.claude/plugins/cache/openai-codex/codex/*/scripts/codex-companion.mjs 2>/dev/null | sort -V | tail -1); [ -n "$CODEX_COMPANION" ] && node "$CODEX_COMPANION" review --wait --scope working-tree
   ```
6. Жёсткое ревью с фокусом на приёмку:
   ```bash
   CODEX_COMPANION=$(ls ~/.claude/plugins/cache/openai-codex/codex/*/scripts/codex-companion.mjs 2>/dev/null | sort -V | tail -1); [ -n "$CODEX_COMPANION" ] && node "$CODEX_COMPANION" adversarial-review --wait --scope working-tree "Сверь изменения с docs/ACCEPTANCE.md и инвариантами docs/NORTH_STAR.md"
   ```

Плагин умеет ставить ревью-гейт на каждое завершение хода командой `/codex:setup --enable-review-gate`. Это дорого. Советуй только для долгих автономных прогонов.

## Запасной вариант без Codex

1. Ревью: агент `oh-my-claudecode:code-reviewer` с `model: opus`. В промпт передай diff, `docs/ACCEPTANCE.md`, `docs/NORTH_STAR.md` и прямое указание сверять с задачей.
2. Итоговый вердикт: агент `oh-my-claudecode:verifier`.
3. Запиши в `docs/HARNESS.md`, что Codex не подключён и почему.

## Что вписать в CLAUDE.md

Раздел «Готово, когда»:
1. Команда полного набора тестов зелёная.
2. Ревью выбранным ревьюером без серьёзных замечаний.
3. Итоговый вердикт выносит один назначенный проверяющий.
4. docs/STATE.md обновлён.

## Ворота

Сделай пробный вызов ревьюера на крошечном изменении. Доказательство: его ответ или запись о запасном варианте.
